# Koukou · QQ 机器人与 Koukou Studio

基于 Node.js 和 OneBot 11 的 QQ 聊天机器人，包含网页控制台、Windows 桌面入口和 NapCat 启动中心。使用 Node.js 内置模块，无需安装 npm 运行依赖。新安装使用通用助手人格，不附带个人角色、专属语料或识图标注。

社区贡献：已合并 [yemuxi520/Koukou-bot](https://github.com/yemuxi520/Koukou-bot) 的管理员、自定义指令、会话人格、记忆管理和可选 LLBot 启动功能，并补充记忆隔离、跨群保护与定时发送回执。

## 可选：LLBot 一键启动（Windows）

以下入口适用于选择 LLBot 的新部署。使用 NapCat 时请按下方“快速开始”和 Windows 部署文档操作，已有 NapCat 启动中心可继续使用。

### 需要准备

| 必需 | 说明 |
| --- | --- |
| Windows 10/11 | 启动脚本是 .bat |
| Node.js ≥ 22 | 项目无 npm 依赖 |
| [LLBot](https://github.com/LLOneBot/LuckyLilliaBot/releases) | QQ 协议端，解压到本仓库**旁边**的 `luckylillia` 文件夹 |
| DeepSeek API Key | <https://platform.deepseek.com> 申请（需充值） |
| 一个 QQ 小号 | 机器人登录用，**建议不要用主号** |

### 步骤

1. 下载 LLBot，解压到与本仓库同级的位置：

   ```
   某个目录\
   ├─ Koukou-bot\        ← 本仓库
   └─ luckylillia\       ← LLBot（里面有 LuckyLillia.exe）
   ```

   放别处也行，把路径写进 `llbot_path.txt`（参考 `llbot_path.txt.example`）。

2. 复制 `.env.example` 为 `.env`，至少填：
   ```ini
   DEEPSEEK_API_KEY=sk-...
   ONEBOT_WS_URL=ws://127.0.0.1:3001
   ```

3. 双击 `start-bot.bat`
   - 自动启动 LLBot（headless，不需要开 QQ 客户端）
   - 等 `.env` 中 `ONEBOT_WS_URL` 对应的本地端口就绪（默认 3001）
   - 打开 `ADMIN_PORT` 对应的机器人控制台（默认 <http://127.0.0.1:8787>）

4. 按 LLBot 配置打开登录页（默认 <http://127.0.0.1:3080>），用手机 QQ 扫码。登录态会保存，但腾讯要求重新验证时仍需人工登录。端口可连接不代表 QQ 已在线，请查看控制台实际连接状态。

### 脚本说明

| 文件 | 作用 |
| --- | --- |
| `start-bot.bat` | 一键启动（全部使用相对路径，放哪都能跑） |
| `stop-old-bot.ps1` | 核对实例锁、入口与进程身份后停止旧实例，避免重复启动 |
| `app.ico` | 快捷方式图标 |
| `llbot_path.txt.example` | LLBot 路径配置模板 |

> 非官方 QQ 接入，**存在账号风险，请自行评估**。仅供个人学习使用。

## 功能

- **对话与人格**：私聊、群内 @ 或引用机器人发言时回复、白名单群按概率主动搭话；人格编辑、会话专属提示词、上下文与长期记忆。
- **人格文件与人格库**：导出当前生效人格或未保存编辑内容；导入 `.txt` / `.md` 时预览、改名并保存，保留已有人格，可选择立即使用或随时切换。
- **会话人格与记忆管理**：可为不同会话选择人格，实际切换时备份并隔离该会话旧记忆；可浏览、清理记忆。清理会保留恢复备份和旧原文，但新会话不再检索旧分区。
- **指令中心**：管理已有功能（含单轮`/Q`解题、点歌、明确索图、拍人、撤回与禁言）和自定义规则的开关、群范围、权限；支持文字/拍一拍、固定/随机/AI 回复、可选自然语言理解、AI 生成规则草稿和 JSON 导入导出。固定与随机规则执行不用模型；`/help` 查看当前会话可用指令。见[指令使用说明](docs/COMMANDS.md)。
- **合并聊天记录阅读**：展开合并转发及嵌套卡片，保留发言人、时间与图片；整份记录按一条外层消息判定主动回复概率，内层消息不单独触发，记录篇幅不放大回复长度。
- **回复行为**：全局默认值、会话覆盖、静音、安静时段、频率限制、长度匹配与分条发送。
- **图片理解**：可配置识图服务商和模型；图片下载重试、哈希缓存、识图结果缓存。
- **群聊总结**：分页读取指定时间窗口、合并实时记录、统计消息与成员活跃度，生成热门话题、群友称号和群圣经。
- **总结中的转发参考**：先判断与群内讨论的关联，再选择性展开相关记录（含嵌套），整张卡片仍计一条消息；相关图片独立交给通义千问读取。转发材料只简短辅助本群真实讨论，不单列转发话题，不增加热度、人数或有效文字样本。
- **定时总结补发**：可选 23:30 检查，只对确认 23:00 没有发送、没有正在生成且 QQ 实际在线的群补发；部分发送或状态不明时跳过。
- **规则互动**：拍一拍回应、白名单群文字、emoji、QQ 自带表情及混合消息自动 +1，无需调用模型。同一连续重复段只跟一次，机器人自己的消息不会起头或触发。图片、图片表情包及混合图片的消息不跟读。
- **定时指令**：在指定群 @ 指定账号发送指令，支持匹配回应后发送后续指令、记录当日执行状态。
- **自定义定时推送**：成功回执落盘去重，离线恢复后只在五分钟内有限补发；结果不明先核对历史，无法确认时不自动重发。此机制独立于群总结的 23:30 查漏安排。
- **群管理**：白名单导入/移除、群名片核对、授权操作与目标成员跟随回复。
- **Koukou Studio**：管理模型、人格、会话、回复行为、群聊报告、日志和记忆；区分进程、OneBot 连接与 QQ 实际在线状态。
- **NapCat 启动中心**：打开登录页、控制进程与计划任务、检查实际连接；安装目录和登录凭据通过独立配置提供。

## 快速开始

需要 Node.js 22 以上、Git，以及已安装并登录的 NapCat。NapCat 使用 OneBot 11 正向 WebSocket 服务端。

```powershell
git clone https://github.com/KimBrine/Koukou-bot.git
cd Koukou-bot
Copy-Item .env.example .env
notepad .env
npm start
```

填写模型 API Key、OneBot 地址/Token 和需要启用的群。控制台默认地址为 <http://127.0.0.1:8787>，端口可通过 `ADMIN_PORT` 修改。

NapCat 的 OneBot 地址、端口和 Access Token 必须与 `.env` 一致。自动 +1 需要在 NapCat 启用 `reportSelfMessage`。首次登录或腾讯要求验证时需要人工扫码或验证码。

详细部署与启动方式见 [Windows 部署](docs/WINDOWS-SETUP.md) 和 [NapCat 启动中心](integrations/napcat/README.md)。

## 配置

`.env.example` 提供配置模板。真实密钥和运行数据由 `.gitignore` 排除。

| 配置项 | 用途 |
| --- | --- |
| `DEEPSEEK_API_KEY` / `DEEPSEEK_BASE_URL` / `DEEPSEEK_MODEL` | 对话模型接口 |
| `VISION_PROVIDER` / `DEEPSEEK_VISION_MODEL` / `DASHSCOPE_MODEL` | 识图服务与模型，需选择支持图像输入的接口和模型 |
| `DASHSCOPE_ENABLE_THINKING` | 千问辅助模型思考模式，默认关闭；支持混合思考的报告、记忆和备用识图型号使用，修改后需重启 |
| `ONEBOT_WS_URL` / `ONEBOT_ACCESS_TOKEN` | NapCat OneBot 连接 |
| `WHITELIST_GROUPS` | 允许主动搭话的群号，逗号分隔 |
| `PROACTIVE_RATE` / `PROACTIVE_RATE_PER_GROUP` | 全局与按群主动搭话概率 |
| `MUTED_GROUPS` / `QUIET_HOURS` | 静音群与安静时段 |
| `REPLY_MAX_LINES` / `REPLY_LINE_MAX_CHARS` | 普通回复行数与单行长度 |
| `SUMMARY_ENABLED` / `SUMMARY_TIMES` / `SUMMARY_GROUPS` | 定时群总结开关、时点与目标群 |
| `SUMMARY_FALLBACK_ENABLED` | 启用 23:30 漏发检查与补发 |
| `SUMMARY_MAX_MESSAGES` / `SUMMARY_MAX_TOKENS` | 输入记录预算与输出 token 预算，消息总数统计不受输入预算裁剪影响 |
| `SUMMARY_CONCURRENCY` | 同时准备的报告群数，默认 2（1～3）；各群失败独立，发送串行且群间隔至少 5 秒 |
| `SUMMARY_TASK_TIMEOUT_MINUTES` | 单群准备总时限，默认 6 分钟（2～30）；覆盖历史拉取、排队、生成和修正，超时取消该群 |
| `SUMMARY_VISION_MODEL` | 群总结参考图片专用通义千问型号，留空沿用 `DASHSCOPE_MODEL`；与普通聊天识图服务独立 |
| `SUMMARY_REFERENCE_MAX_IMAGES` | 每份报告最多读取的参考图片数，默认 6（0～12）；0 只展开文字 |
| `SUMMARY_SEND_MODE` | `forward` 合并转发或 `split` 按报告条目发送 |
| `AUTO_PLUS_ONE_ENABLED` | 文字、emoji、QQ 自带表情及混合消息自动 +1；仅白名单群，独立于普通聊天静音/安静时段 |
| `DAILY_PING_*` | 定时 @ 指令与后续指令 |
| `ID_CHECK_*` | 群名片规则、目标群与授权操作者 |
| `ADMIN_ENABLED` / `ADMIN_PORT` | 控制台开关与端口 |
| `NAPCAT_DIR` / `NAPCAT_TASK_NAME` | Windows 控制台重启 NapCat 所需的目录与计划任务 |

控制台的「沿用全局」表示使用「回复行为」中的默认值。取消继承后可为该会话设置独立参数。标注「需重启」的配置在重启机器人后生效。

「人格编辑」中的人格库保存在**当前实例数据目录的 `personas/`**，不同实例互不共享。点击「导入文件」选择 `.txt` 或 `.md`（最多 256 KB），预览正文和名称后保存；同名人格不会被覆盖，默认仅保存，勾选「导入后立即使用」才会切换。可在列表中选择任意人格并点击「切换使用」，下一条消息开始生效。仓库中的参考文件不会自动导入或激活。

自定义人格、拍一拍语料、装饰偏好、聊天补充规则和识图资料均属于私有实例数据，代码更新与 Git 推送不携带这些资料。默认人格与拍一拍语料均为通用示例。部署目录、文件格式及 **1.x 升级前的人格备份/迁移步骤**见 [私有资料与公开默认值](docs/PRIVATE-PROFILES.md)。

「导出当前使用」下载运行中实际采用的人格；「导出编辑内容」下载编辑框文字，包括尚未保存的改动。导出为 UTF-8 `.txt`，仅包含人格正文，不附带密钥、记忆或聊天上下文。导入支持 UTF-8、UTF-16 和常见中文文本编码。

人格切换是**全局操作**，所有群聊和私聊同步生效。实际改变人格名称或正文时，先在私有数据目录的 `config-backups/persona-switch-*.json` 保存近期与长期记忆快照，再重置所有会话记忆、旧人格待发回复和待整理内容，开启新的原文检索分区。群总结原始记录、人格库、登录态和已完成的定时指令记录保留。切回旧人格同样从新记忆开始；重复启用未改变的人格不会清空记忆。保存编辑只更新人格库，点击「切换使用」后应用；保存和切换失败时不会宣称成功。

## 长期记忆与原文检索

近期窗口外的消息先保存为私有原文档案，再整理成分会话的事实摘要。摘要优先保留人物偏好、明确约定、关键数字和时间、未完事项及更正，保留原话归属；不再将每条待整理消息预先裁成150字。摘要为空、过长或写入失败时保留原批次重试，不用截断后的半句话替换旧记忆。同一会话的压缩请求不会并发覆盖。

普通回复和盯人回复按当前话题，从本会话、当前人格分区的原文索引中检索相关旧消息，最多补入4条、1400字背景；回复长度仍遵守原设置。「数据与记忆 → 长期记忆摘要」也可输入话题查看相关原话，无需安装外部插件或调用额外的检索模型。

原文档案位于数据目录的 `long-memory.json.records/`，不纳入版本控制。检索使用文字片段匹配，索引最多保留每会话最近3000条归档消息，重启时最多读取对应文件末尾4 MB；更早的原文仍留档，但不自动检索。它不能保证找回所有隐含关联，也不能恢复旧版已经丢弃的内容。人格切换保留旧分区用于备份恢复，但新分区不读取旧人格资料。档案会随使用增长，可在停止机器人后自行备份归档。

引用机器人自己发送的消息视为直接对话，无需另加 @，沿用「被 @ / 引用时回复」开关、静音、安静时段和直接回复额度。引用其他群友的消息仍按普通群消息处理。引用读取失败且没有可靠的缓存对应关系时，不猜测引用作者。

合并聊天记录只是当前消息的阅读资料，默认最多读取 80 个节点、6 层嵌套、12 张卡片、16000 字和 8 张图片，读取等待最多 8 秒。达到上限或部分读取失败时会明确标记缺失；不会把内层的 @、引用或指令当作外层触发。白名单群中的普通转发按原有概率与冷却决定是否回复，外层 @ 或引用机器人时按直接对话处理；未命中时可随其他消息进入已启用的上下文。回复长度按外层文字计算，未回复记录留在上下文后也不会放大下一条回复。

## 本地角色辨认资料

可在实例数据目录的 `vision-knowledge/rules.json` 中维护 `characters`（名称和别名）、`prompt`（对照特征）、`cues`（触发比对的线索）、`references`（角色名与同目录参考图文件名）及 `exact`（图片 SHA-256 对应的人工确认名称和描述）。提供至少两张、最多三张参考图，每张最多3 MB；重新加载机器人后生效。未提供资料时沿用普通识图流程。

参考资料只用于识图，不进入聊天历史或群统计。相关候选图会多一次有时限的参考比对；识图资料更新会使用新缓存范围。证据不足时不强报候选姓名，模型仍可能识别错误。这些实例资料、图片和人工标注均保存在私有数据目录，不随源代码提交。

## 登录后的聊天衔接

登录或重连后，补发的旧消息仍进入所跟踪会话的上下文和群总结，作为背景信息阅读；旧消息不会触发补答、执行旧指令、盯人回复或自动 +1。机器人从登录后到达的新消息衔接当前话题。

判断使用 QQ 的发送时间：登录前的记录、超过 90 秒才到达的消息，以及缺失或异常发送时间的事件，均不触发即时回复。上下文按时间排列并注明历史背景；近期窗口放不下的消息交给已启用的长期记忆。既有无时间的记忆仍保留，作为时间未知的背景读取。

如果期间发生过人格切换，早于切换边界的补读消息不再写入新人格的聊天记忆，仍可进入群总结原始记录。

断线前尚未发出的回答不会在恢复后补发。群聊主动回复在生成期间遇到新话题时会取消旧回答；盯人队列同样会清除过期记录，避免安静时段结束或恢复连接后集中补答。

## 群总结

群内 @ 机器人发送 `/群总结`，或者在私聊中触发总结。支持「今日总结」「昨天总结」「三天总结」等时间窗口，具体识别逻辑见 `src/dailySummary.js`。

```text
🎯 群聊日常分析报告
📅 日期 / 时间范围

📊 基础统计
• 消息总数: …
• 参与人数: …
• 总字符数: …
• 表情数量: …
• 最活跃时段: …

💬 热门话题
1. 话题标题
   参与者: 示例群友甲、示例群友乙
   围绕真实讨论，概括主要内容、结论和安排。

🏆 群友称号
• 示例群友甲 - 称号 (MBTI)
  根据实际活跃数据写简短理由。

💬 群圣经
1. "原始发言" —— 示例群友乙
   简短点评。
```

统计由程序计算，模型负责定性描述。输入超出预算时优先普通文字并覆盖完整时间窗口；固定指令和模板回复压缩后参与选题，原始记录仍参与总数统计。话题数量使用完整窗口的有效普通文字样本，采样不会降低数量要求：

| 有效普通文字消息 | 热门话题数量 | 优先数量 |
| --- | --- | --- |
| 不超过 40 条 | 允许 1–2 项 | 按实际内容 |
| 41–199 条 | 3–5 项 | 3 项 |
| 200–799 条 | 3–6 项 | 4 项 |
| 800–1999 条 | 4–8 项 | 6 项 |
| 2000 条及以上 | 6–10 项 | 8 项 |

低于对应最低数量或超过上限时，自动要求基于原记录重新梳理一次；不无限重试。只保留有真实交流、独立问题或重要安排支撑的话题，不为数量编造或拆碎同一事件。纯图片占位、固定模板和转发内层消息不放大话题预算，活跃时段数也不等于话题数；只有转发资料而没有有效群内交流时不凑话题。群友称号仍最多 5 位。

总结时，合并聊天记录先通过外层引用、已有卡片摘要/附带说明和附近十分钟的真实群内讨论筛选，不额外调用模型判断。明确引用这条记录（或有限回复链）、摘要与多条附近讨论有共同关键词、附近讨论明确指向刚分享的记录时，才按关联依据优先选择、展开完整及嵌套内容。没有摘要和关联依据的卡片默认不展开、不下载图片、不调用视觉模型；“没有选中”只表示依据不足，不表示已读或确定内容无关。这会减少无关资料输入及识图请求，但可能漏选没有显式关联线索的材料。

选中的记录仅作为低权重参考，内层人物、发言、原话和图片不参与本群统计。只有本群成员确实围绕材料交流时，才能在相应话题中简短补充；没有群内交流证据则省略。模型使用内部来源标记区分参考句，发送前移除标记，超出话题正文 20% 或 60 字的参考整句会被省略。转发资料不能单独凑热门话题，也不能用内层原话凑本群群圣经；只有资料、没有有效群内交流时如实说明不足。筛选只影响群总结，普通聊天的合并记录阅读规则继续生效。

参考材料正文预算约为主记录文本的 15%（最低 200、最高 4000 字），最多选择 12 条外层来源并覆盖窗口首尾；展开和读图合计最多等待 60 秒，仍受单群准备总时限约束。图片使用 DashScope 密钥和专用通义千问模型，复用普通聊天的图片哈希缓存，描述缓存按模型与总结读图提示分别保存。读取失败、节选或达到上限会标记未知内容，继续处理已确认的群内讨论。

报告按条目分开发送，保留条目内普通换行、多行引文和解码后的 `\n`。昵称优先使用群名片；热门话题的参与者栏和正文共用昵称映射。

定时总结按北京时间排期。启用补发后，发送回执保存在 `data/summary-delivery-state.json`；发送失败、部分发送或无法确认历史时会避免整份重复发送。23:00 与 23:30 都离线的当晚不追补。

每次总结在开始准备时固定消息窗口的截止秒（不含截止秒本身），历史分页和实时捕获合并使用相同窗口。扫描期间的新聊天继续正常捕获，不延长本次总结窗口；截止点之前新补齐的旧消息仍须重复核验，历史未完整时不发送残缺报告。

定时任务遇到实际在线探针短暂超时会有限重试，只有重新核验成功才发送；连续未确认只暂缓当前群，其他群继续各自核验，明确掉线仍停止。模型内容检查拒绝正文时自动发布标注为「统计版」的报告，仅包含代码统计和原因说明；不包含原话、推测话题或虚构称号，并沿用完整历史与发送去重检查。

手动查漏补发可在23:30已检查后重新执行，但仍先确认目标群未发布、QQ在线且没有未确认发送。控制台接口 `/api/action/summary` 的 `missingOnly: true` 支持可选 `groupId` 限定已配置报告目标群，`statsOnly: true` 可只补统计版；自动时点和普通聊天回复规则不受此人工请求影响。

白名单群与明确配置的定时目标群都会实时保存总结记录，手动总结无需加入定时目标。新加入的群可能只能从 QQ 取得一部分旧历史；记录稳定不等于已经覆盖当天零点。历史未完整时会明确说明原因及可见边界，不发布冒充全天的残缺报告；后续收到的消息继续存档。

## 使用前了解

本项目通过非官方客户端接入 QQ，账号可能受到登录限制。请遵守平台规则，避免骚扰和批量发送。NapCat、QQ 客户端和其二进制文件需单独安装，仓库提供对接源码与自定义启动界面。

### 单次解题模式

私聊发送 `/Q 问题`，或在群里明确 @机器人并带 `/Q`，仅对当前问答启用认真讲解。支持文字和题目图片，保留推导、公式、代码和分段；下一条未带 `/Q` 的消息恢复普通聊天。引用或嵌套聊天记录中的 `/Q` 不会触发。沿用会话总开关、静音与现有权限。控制台“显示思考耗时”只对 `/Q` 回复生效；旧的全局长回答开关不再使用，模型思考强度仍由模型设置决定。

### 表情包库与文字配图

每张表情包可“仅删除”或“拉入黑名单并删除”。黑名单按SHA-256阻止相同文件再次学习、上传或替换，重启后继续有效；在黑名单管理中解除后可重新收录，但不会自动恢复图片。裁剪、重新压缩或修改后的文件哈希不同，需要单独屏蔽。黑名单采用可搜索的图片卡片，支持点击放大、查看拉黑时间、复制哈希和解除。拉黑后的图片独立归档仅供预览，不参与选图或发送；旧记录尝试按完整哈希从已有图片缓存找回，找不到时显示无预览，拦截仍有效。解除不会自动放回活动库。黑名单和预览归档仅保存在实例私有数据目录。

控制台“表情包”页支持大图预览、替换图片、编辑名称/标签/描述/适用场景、显示与复制SHA-256，以及按这些字段搜索。换图后重算哈希，保留条目；重复图片拒绝覆盖其他条目。资料保存在实例私有数据目录，不随Git发布。

表情包必须跟随成功发送的普通聊天文字；普通聊天每轮默认35%机会配图，模型主动选图也遵守概率。当前用户明确要求发送表情包时不抽概率，直接从库中选图并尝试发送，仍遵守开关、发送范围、黑名单和冷却；0概率仅关闭自动配图。可调整0～100%概率、每轮最多1～3张、选图方式、发送范围与同一会话配图间隔。选图可按模型理解语境（没有贴切图片就不发）、仅模型点名或用户明确选择随机模式。自动语境配图只接受模型给出的库内完整名称，不使用关键词碰撞、历史使用相似度或随机候选补位；35%是整轮的配图机会，不保证命中后一定发图。明确索图仍可按语境或随机选一张。学习范围与发送范围分别设置；不会扩大机器人原有的回复权限。群总结、指令回执和/Q解题不自动配图。控制台手动发送也必须填写文字，但不抽取概率。

### 开发分支功能合并

控制台可设置最小回复预算（并非强制输出字数，仍受行数和单行上限限制），从好友/群列表添加会话，管理多套自定义识图接口并即时切换。模型自动检测仅读取服务商列表，请选支持图片的型号。每轮识图固定使用开始时的客户端，换模型后缓存独立。

表情包可开启私聊学习（默认关闭），与群采集共用额度并遵守黑名单及两阶段审核。图库每3秒检查更新；有未保存设置或编辑时会暂停刷新。新增的多接口资料、Key与表情包等仍存实例私有目录，不进入公开仓库。

联网搜索卡片可即时保存开关、渠道和通义型号；自动模式按可用Key选择千帆、DeepSeek、通义、必应。指定渠道缺少Key会提示错误，不暗中切换服务商。搜索结果缓存10分钟，每轮最多执行两次搜索；真实接口可用性和计费由服务商决定。DeepSeek接口按[官方搜索文档](https://api-docs.deepseek.com/zh-cn/guides/search/)实现，通义来源参数按[官方联网搜索文档](https://help.aliyun.com/zh/model-studio/web-search/)实现。

直接问答可用“点歌 歌名 歌手”、歌曲ID或完整链接，选择网易云（默认）或QQ音乐并尝试发送音乐名片；开关、范围、权限及配置导入导出均在指令中心管理。清理非白名单群需要控制台确认，执行前在私有数据目录的config-backups/group-cleanup-*备份记忆、会话设置和日报；不会在升级时自动清理任何会话。

控制台前端按ui.html、app.js、ui.css拆分；普通聊天MAX_TOKENS可即时调整，默认4096，不改动已有实例设置或群总结独立预算。看门狗从windows.local.json指定的环境文件读取端口，先核对监听进程归属；DryRun不启动任务也不写状态。

### 按歌手、ID和链接点歌

群聊需明确@机器人，私聊直接发送。未注明平台默认网易云；QQ音乐需注明平台，完整歌曲链接自动识别平台。

```text
点歌 浮光 周深
来一首周深唱的《浮光》
点歌 《浮光》 周深
点歌 436016480
点歌 https://music.163.com/song?id=436016480
QQ音乐 点歌 浮光 周深
点歌 QQ音乐 97773
点歌 QQ音乐 MID 0039MnYb0qxYhV
点歌 https://y.qq.com/n/ryqq/songDetail/0039MnYb0qxYhV
```

默认空格前是歌名、后是歌手；有明确自然语言说明时按描述处理。英文多词或复杂描述可由当前模型辅助解析，但不猜测输入里没有的名称、平台或ID。也可引用歌名或完整链接，说“想听这个，发给我”。

指定歌手后只选择歌名和歌手相符的候选；数字ID直接查歌曲详情，不模糊搜索、不自动补位。QQ音乐MID先查出数字歌曲ID，再发对应平台的原生音乐名片。找不到、平台冲突或查询失败会提示；只支持网易云和QQ音乐完整单曲链接，短分享链接请换成完整链接或ID。仅查询公开歌曲资料，不下载音频；名片能否播放取决于平台与账号权限。

### 拖拽上传与AI标注草稿

表情包页可拖入或选择图片，一批最多20张、单张最多4MB，支持PNG/JPEG/WebP/GIF。逐张预览、填写名称/标签/描述/场景，或批量追加标签和场景；点击上传才进入图库。AI补全使用当前表情包第二轮复核/打标模型，只补空白项，不覆盖手工填写；调用需要该模型API，结果仍需检查并点击上传。未确认是表情包或调用失败时保留草稿，可手动填写继续。草稿保留在当前浏览器页面内存，切换控制台页签不丢失；刷新或关闭整个页面会丢失未上传草稿。

### 版本与更新提醒

工作台的“版本与更新”显示当前运行版本，可手动检查GitHub上的正式版本；发现更高版本时，在左上角品牌区下方提醒。读取官方仓库最多100个公开标签，按语义版本比较，不追踪dev或预发布标签。自动检查缓存6小时，失败缓存15分钟，手动检查最短间隔30秒；访问失败明确显示，不能据此认定已是最新。这里只提示并链接新版，不自动下载、执行git或覆盖配置；更新前请备份私有配置和数据。没有更新检测功能的旧版需要先升级到v2.18.0或之后版本，才能获得后续提醒。

自动+1支持连续相同的纯文字、纯Unicode emoji、纯QQ自带表情，以及三者的任意混合；仍保留内容顺序、空白及表情编号/随机结果的区分。只在白名单群运行，同一连续段只跟一次，机器人自身消息不计数也不能起头；图片、图片表情包及混合图片的消息均不跟读，不受静音和安静时段限制，不调用AI。
